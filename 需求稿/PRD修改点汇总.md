## 〇、评审结论（一页纸）

1. **方向可行**：Trade Master 深度引擎适合做托管的「信号/研究层」，但**不能黑盒直接驱动调仓**——它是单标的、10–15 分钟/次、输出离散评级，不是"持仓组合→买卖指令"的执行器。
2. 正确用法是**两级架构**（与你的 A4 答复一致）：
   - **计划层（慢，深度引擎）**：每日收盘后对"在管标的"并行跑 `run_analysis`，产物 = 评级 + 分节报告，入库作为「AI 调仓报告」。
   - **执行层（快，分钟级，新写）**：每分钟扫 Wind 行情，把最新评级翻译成动作 + 硬风控（止损/次数/仓位上限）即时触发；命中才生成委托 → 撮合 → 成交 → 更新账务 → 发通知。**单笔执行 <500ms 指这条路径**，不含深度分析。
3. 需要**新写**的不是引擎，而是 App 主体（账务/撮合/持仓/自选/托管调度/流水/通知/对话上下文）——这些本来就是新产品的全部工作，与"复不复用引擎"无关。
4. **引擎侧增量很小**：缓存表 + 评级→动作映射 + 可选并发/持仓上下文注入。详见 §7。

## 三、财团托管：产品规则（改 4.4 / 5.3，落地 A3）

### 3.1 托管是什么
- 内置 **1 个「财团」**（复用引擎 bull/bear/research/risk/portfolio_manager 多智能体分工），`agent_id` 固定不可选。
- 用户差异化靠**托管风格 + 风控参数**表达：保守 / 均衡 / 进取（预设 3 档映射到目标仓位与换手强度）。

### 3.2 调仓信号来源（A3#1）
- 以深度引擎评级为主信号：`Buy/Overweight → 加仓档`、`Hold → 持有`、`Underweight/Sell → 减/清仓`。

### 3.3 触发方式（A3#2，默认，待确认）
- **日计划**：每交易日收盘后，对在管标的并行跑深度分析 → 生成次日「评级+目标仓位」计划。
- **盘中执行**：分钟级扫行情，按最新计划动作执行；硬风控（止损线等）实时即时触发，不依赖深度引擎。
- 不盘中实时触发 10–15 分钟的深度分析。

### 3.4 标的池（A3#3 + B3：持仓 / 自选 / 全市场）
- 用户选三项之一（以 UI 托管设置页为准）。
- 持仓 / 自选：直接以用户列表为池，逐只深度分析。
- **全市场的定义（默认，待确认）**：不做全 A 实时扫描；以「持仓 + 自选 + Agent 候选池」为标的，Agent 每日从 Wind 涨跌幅/新闻粗筛 **≤3 只候选**做深度分析后给出「建议新增」。防止数据/LLM 账单失控。

### 3.5 风控（A3#4）
- 硬校验（不可关）：现金/持仓充足、100 股/手取整、T+1 可用量、涨跌停/停牌不可成交、单票仓位上限硬顶。
- 可选参数（用户在托管设置里配）：单日最大交易次数、单票最大仓位、单票止损比例。

### 3.6 触发方式触发 → 对应 A4
- 分层确认（你已答"对"）：执行器 <500ms；报告=读决策库，新标的情况才异步触发深度分析。

## 四、账务规则（新增章节，落地 A5）——双簿模型（用户裁定）

账户下**两本相互独立**的持仓簿：

1. **镜像簿（交易首页/持仓页）**：
   - 未同步：50w 种子现金 + 空持仓；**首次同步**：50w 清空，镜像 = 用户真实持仓（OCR 成本价入库、现价计市值），现金 = 0，`total_assets = Σ(现价×数量)`。
   - 「一般同步」**无限制**，随时覆盖为最新真实快照；**不影响托管簿**。
2. **托管簿（财团托管页）**：
   - **开启托管前须在托管页粘贴持仓截图** → 建立托管簿起始快照（独立于首页镜像，须单独粘贴，不能直接用首页镜像）。
   - 之后只被托管调仓改变；首页同步不触碰。
   - **重贴快照 = 重建托管簿**（2026-09 改）：允许直接重新粘贴；提交时自动清空委托/成交/次日行动计划（**监控条件随之清空**）→ 用新快照覆盖持仓与可用资金 → **同时关闭托管开关**，需回「策略设置」手动重开。粘贴面板第 1 步即常驻横幅写明覆盖影响，提交时再二次确认。
     - 关开关的原因：计划被清空后执行层会回落到「按旧评级兜底」的路径，下一秒就可能拿**旧仓位**的评级给**刚贴进来的新仓位**下单。
     - 「**清空成交记录**（重置托管）」独立保留，语义是**回到未建簿状态**（不做覆盖，只清空）。
   - 托管收益率/归因只基于托管簿，从托管簿建立日起算。
3. 托管簿**可用资金 = 0**（用户裁定：先卖后买、换仓式，无凭空资金）→ 托管本质是组合再平衡，买入资金以卖出解锁为限。
4. **展示口径（用户裁定：首页合并展示）**：
   - 交易首页资产看板 = **合并口径**（镜像簿总资产 + 托管簿总资产），可展开分看两簿；
   - 财团托管页 / 归因看板 = 只看托管簿；
   - AI 对话持仓诊断默认合并口径，可限定「托管 / 首页」。
5. 同步之后的交易：按撮合规则在各自簿内正常增减资金与持仓。

## 五、撮合规则（新增章节，落地 B1）

- 成交价：**现价即时成交**（Wind 最新价）。
- A股：100 股/手取整、T+1（当日买入不可卖）、涨跌停/停牌不可成交。
- 港股/美股：美股 T+0、无涨跌停；港股最小交易单位因股而异 → **本期简化为按股撮合**（不做精确手数，需你确认）。
- 费用：**用户可配置**。托管设置中由用户填写：佣金费率、是否免 5 元（免五开关）、印花税费率；默认预设 = A股 佣金万 2.5（最低 5 元）+ 卖出印花税 0.05%。港股/美股本期按股撮合、费用沿用用户填写的同一套（是否分市场独立，见 §9 空项 4）。费用配置进 `trust_config`/账户模型。
- 卖出校验可用数量，买入校验可用资金；失败则委托置「废单/已撤」并记录原因。

## 六、行情与成本（改 7.1，落地 B4/B5）

- **行情全走 Wind**（首页资产/持仓/委托 + 托管分钟级扫描）。
- 前端轮询降频：资产/持仓页 15s 级，托管扫描 60s 级（控 Wind 调用量与费用）。
- 非功能指标按内测规模定档（并发几十），删除 1000 QPS / 99.9% 模板指标。
- 明确 **Wind 欠费/鉴权失败的降级与错误文案**（已实现 VendorRejectedError，前端按余额不足/限流两类提示）。
- 成本提醒：托管「日计划全池深度分析」= N 只 × 深度分析调用，属主要账单项；全市场候选池 ≤3 只，前端轮询降频，共同压成本。
