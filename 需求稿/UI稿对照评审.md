# UI 稿对照评审（以需求稿为准）

> UI 稿：`~/Downloads/ai-sim-trading-web/index.html`（已实现的 Web 原型，含 design token / 响应式 / 交互 JS）
> 需求稿：`模拟交易AI托管App_PRD_修订版.md`（权威）
> 原则：一切以需求稿为准；UI 稿仅作视觉/组件参考，可复用其元素。

## 〇、结论

1. UI 稿是一份**高质量可直接复用**的前端原型，其 design token、组件、深/浅主题、桌面侧边栏 + 移动底部 Tab 的响应式骨架**全部可保留**作为前端 base。
2. UI 稿整体基于**旧 V1.0**（自选/量化还是 V1.1 占位），与修订版 PRD（本期全量）有几处**方向性冲突**，需按需求稿修正。
3. 需求稿新增的**双簿模型、个股详情、托管归因、托管建簿、风格/费用设置**，UI 稿**尚未覆盖**，需补页面/状态。

| # | UI 稿现状 | 需求稿要求 | 处理 |

| 2 | **首页资产看板 = 单一口径**（500,000 总资产） | **双簿合并口径**（镜像簿 + 托管簿求和，可展开分看） | 首页 KPI 需支持合并 + 拆分 |

## 四、可调和项（不算冲突，定个口径即可）

1. **当日委托/成交**：UI 稿把它作为托管页第三个子 tab「委托成交」；需求稿是独立页 `/records`。→ 建议：保留独立页入口，同时托管页内嵌最近记录（两者共用数据，UI 稿内嵌卡片可复用）。
2. **首页右侧「AI 策略动态」侧栏**：UI 稿独有元素，需求稿未明写，但与「AI 调仓记录」一致。→ 保留（桌面端展示 AI 事件流，是好元素）。
3. **品牌名**：UI 稿「AI模拟交易」；需求稿主打「财团托管」。→ 定一个主品牌名 + 副标语（建议「AI 模拟交易」为主、托管为功能卖点）。

## 五、前端关系与落地建议（已裁定）

1. **旧 Trade Master 深度引擎前端（`static/index.html`）舍弃**；深度分析引擎（后端 `run_analysis` / TradingAgents）保留，但其**唯一交互入口 = 新 App「AI 对话助手」**：用户在对话里发「深度分析 600519 / 分析贵州茅台」→ 走 intent → plan → 异步跑引擎 → 结果以**报告卡片**（评级 + 分节报告）在对话流里展示。
2. 本 UI 稿 `index.html` 复制进 repo 作为**新 App 前端 base**（可放入 `product/trade_master/app_frontend/` 或独立目录，见下）。
3. 开发顺序：在 UI 稿骨架之上，按 §二/§三 补齐冲突与缺口；深度分析相关交互只做「AI 对话助手」内的报告卡片，不做独立分析页。

> 落地目录（**已裁定**）：`product/trade_master/app_frontend/`（前后端同 repo）；旧 `static/index.html` 归档（改名/移出，不删除，保留作参考）。
